# 자율주행 파이프라인 지도 — 이 로드맵 전체의 안내판

> Chapter B 산출물. 모든 로봇은 하나의 루프이고, 자율주행은 그 "판단" 상자 속 4단계다.

## 로봇 = 감각 → 판단 → 행동 루프

```
        ┌─────────────────────────────────────┐
        │                                     │
   [감각]           [판단]              [행동]  │
   센서  ──────▶  컴퓨터  ──────▶  액추에이터 ──┘
   LiDAR·카메라    "어디지? 뭐가     모터(바퀴)
   엔코더·IMU      보이지? 어디로    스피커·LED
   범퍼            갈까?"
        └───────── 초당 수십 번 반복 ──────────┘
```

"로봇이 부드럽게 움직인다" = "아주 잘게 쪼갠 판단이 아주 빠르게 반복된다".

## 판단 상자를 열면: 4단 파이프라인

```
   인지            위치추정          계획             제어
   Perception      Localization     Planning         Control
   "주변에 뭐가     "지도에서 나는    "어떤 길로        "그 길을 따라가려면
    있나?"          어디에 있나?"     갈까?"           바퀴를 어떻게?"
      │               │               │                │
      ▼               ▼               ▼                ▼
   이 로드맵에서 직접 만드는 장:
   N (매핑)        O (MCL)          P (A*)           Q (경로 추종)
   ────────────────── 그리고 R장에서 프로덕션(Nav2)과 비교 ──────────────────
```

- 지도 만들기(매핑)는 인지의 축적이고, 위치추정의 전제다 (지도가 있어야 "지도에서 어디"가 성립)
- Part 2(F–H)의 수학은 이 네 단계 전부의 공용 부품(좌표 번역기)
- HAL(D장)은 파이프라인 전체와 "몸" 사이의 계약

## 5분 스토리: 호출 벨 → 테이블 도착 (단계 매핑)

| # | 일어나는 일 | 파이프라인 단계 | 로드맵 챕터 |
|---|---|---|---|
| 1 | 벨 신호 → "T3로 가라" 임무 하달 | (자율주행 밖 — 태스크 할당) | Part 6 (멀티로봇) |
| 2 | "T3" → 지도상 포즈(x, y, θ)로 해석 | 지도/POI | N |
| 3 | "나는 지금 어디?" — 오도메트리 + LiDAR·지도 대조 융합 | 위치추정 | O |
| 4 | 현재 위치 → T3까지 경로 탐색 | 계획(전역) | P |
| 5 | 경로 위에 로봇을 붙잡아두는 바퀴 속도 계산, 초당 수십 번 | 제어 | Q |
| 6 | 그 와중에 지도에 없는 것(사람·의자) 감시 → 정지/우회 | 인지 + 계획(국소) | N, S |
| 7 | 목표 포즈와의 차이 < 임계값 → 최단 방향 정렬 회전 → `ARRIVED` | 제어 + 상태 머신 | 문제 1-2, D |

## 실패는 어느 단계인가 — 디버깅 첫 질문

같은 "충돌"이라도:
- **못 봤다** (유리, 낮은 턱, 범퍼뿐인 로봇) → 인지 실패 → 센서 보강/가상 벽
- **내가 어딘지 착각했다** (지도상 위치가 틀어짐) → 위치추정 실패 → 재위치추정/지도 품질
- **길을 이상하게 잡았다** → 계획 문제 → 코스트맵/파라미터
- **길은 맞는데 못 따라간다** → 제어 문제 → 튜닝

증상은 비슷해도 처방은 전부 다르다. "어느 단계의 실패인가"가 로봇 디버깅의 첫 질문.
