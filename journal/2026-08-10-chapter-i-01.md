# [Chapter I] cmd_vel에서 odom까지 - ROS 2 콜백과 QoS의 실제 동작 - 2026-08-10 (Week 06)

## 이번 주 목표
- ROS 2 C++ 노드가 `cmd_vel`을 구독하고 H장에서 만든 오도메트리 함수로 포즈를 적분
- 계산된 포즈와 속도를 `nav_msgs/msg/Odometry`로 발행
- QoS 불일치를 직접 만들어 메시지가 전달되지 않는 이유를 확인
- executor, callback group, mutex가 콜백 실행과 공유 상태를 어떻게 제어하는지 실험

## 한 것
- `fake_robot` ROS 2 패키지 작성
  - `geometry_msgs/msg/Twist` 기반 `/cmd_vel` 구독
  - 500 ms wall timer에서 실제 경과 시간 `dt` 측정
  - H장의 `robomath::integrate_odom`을 재사용해 `(x, y, theta)` 적분
  - `nav_msgs/msg/Odometry` 기반 `/odom` 발행
- 2D 헤딩을 quaternion으로 변환
  - `z = sin(theta / 2)`, `w = cos(theta / 2)`
  - `odom`과 `base_link` 프레임 관계 명시
- 토픽 성격에 따라 QoS 분리
  - `/cmd_vel`: `RELIABLE`, `VOLATILE`, `KEEP_LAST(1)`
  - `/odom`: `BEST_EFFORT`, `VOLATILE`, `KEEP_LAST(5)`
- executor와 callback group 실험
  - `SingleThreadedExecutor`에서 긴 구독 콜백이 타이머까지 지연시키는 현상 확인
  - `MultiThreadedExecutor`만 적용해도 기본 `MutuallyExclusive` 그룹에서는 직렬 실행됨을 확인
  - 타이머와 구독을 별도 callback group으로 분리해 동시 실행
  - 명령 속도 한 쌍을 mutex 아래에서 지역 스냅샷으로 복사

## 구조 - 명령이 오도메트리가 되는 순서
```text
/cmd_vel (Twist)
  -> subscription callback
  -> mutex로 linear.x / angular.z 갱신

500 ms timer callback
  -> 명령 스냅샷 복사
  -> 실제 dt 계산
  -> 좌우 바퀴 이동량 dl / dr 계산
  -> integrate_odom
  -> theta를 quaternion으로 변환
  -> /odom (Odometry) 발행
```

## 막힌 것 -> 어떻게 풀었나
- **`geometry_msgs`, `nav_msgs` 헤더에 빨간 줄**: 패키지 의존성을 `package.xml`과
  `CMakeLists.txt` 양쪽에 추가하고 compile database를 다시 생성한 뒤 clangd를 재시작했다.
- **robomath 링크 시 CMake 오류**: Jazzy의 `ament_target_dependencies`가 사용하는 plain 링크
  문법과 `PRIVATE` 키워드 문법이 한 타깃에서 섞였다. `robomath` 링크를 plain 문법으로 통일했다.
- **직진 거리가 두 배로 계산됨**: `fixed_dt`가 각속도 항에만 곱해지고 있었다. 좌우 바퀴
  속도 전체에 `dt`가 곱해지도록 괄호를 수정했다.
- **타이머 주기와 실제 dt를 같은 값으로 봄**: 500 ms는 실행 요청 주기일 뿐 실제 콜백 간격은
  조금씩 달랐다. `current_time - previous_time`으로 실제 경과 시간을 측정했다.
- **QoS depth가 CLI에서 `UNKNOWN`으로 표시됨**: 설정 누락이 아니라 Jazzy의
  `rmw_fastrtps_cpp` 그래프 조회가 history/depth를 노출하지 않는 경우였다. Reliability와
  Durability 및 실제 통신 결과로 설정을 검증했다.
- **VOLATILE 과거 메시지 실험이 입력 대기 상태가 됨**: `ros2 topic pub --once`가 기본적으로
  구독자 한 명을 기다렸다. `--wait-matching-subscriptions 0`을 사용해 구독 전에 발행했다.
- **MultiThreadedExecutor인데도 타이머가 멈춤**: 두 콜백이 같은 기본
  `MutuallyExclusive` callback group에 속해 있었다. 그룹을 분리하고 공유 명령을 mutex로
  보호했다.

## QoS에서 확인한 것
```text
Publisher       Subscriber      결과
RELIABLE        RELIABLE        수신 가능
RELIABLE        BEST_EFFORT     수신 가능
BEST_EFFORT     BEST_EFFORT     수신 가능
BEST_EFFORT     RELIABLE        수신 불가

VOLATILE
  -> 구독 전에 발행된 메시지는 받지 못함

TRANSIENT_LOCAL
  -> 퍼블리셔가 살아 있으면 늦게 접속한 구독자도 저장된 메시지를 받음
```

## 배운 것 한 줄
> ROS 2 토픽은 타입만 맞는다고 연결되는 것이 아니라, 시간과 QoS와 콜백 실행 정책까지 맞아야 동작한다.

## 검증
- `fake_robot` 패키지 빌드 성공
- `robomath` 테스트 7개 전체 통과
- 곡선 명령 `linear.x=0.4`, `angular.z=0.2`에서 `x`, `y`, `theta` 변화 확인
- 정지 명령 후 포즈 고정 및 `/odom.twist`가 0으로 변경됨을 확인
- quaternion의 `z^2 + w^2`가 약 1임을 확인
- `BEST_EFFORT` publisher와 `RELIABLE` subscriber의 QoS 불일치 경고 확인
- 별도 callback group에서 2초 구독 콜백 실행 중에도 타이머가 약 500 ms 간격을 유지
