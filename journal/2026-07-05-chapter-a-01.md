- VS Code "Reopen in Container"로 컨테이너 안에서 개발하는 워크플로 확립 (에디터·터미널·clangd 전부 리눅스 기준으로 동작)
- `hello_ros` 패키지(package.xml, CMakeLists.txt, hello_node.cpp)를 손으로 타이핑 → `colcon build` → 1초마다 발행하는 첫 노드 실행 성공. C++ talker와 Python listener가 서로 대화하는 것도 확인
- 문답으로 배운 툴체인 개념들을 [학습 노트](../docs/notes/chapter-a-toolchain.md)로 정리 (colcon·CMake·make/ninja·g++·clangd의 관계, rcl/rclcpp, ament, GNU/LLVM까지)

## 막힌 것 → 어떻게 풀었나

### 1. 이미지가 조용히 amd64로 내려옴
- 증상: `osrf/ros:jazzy-desktop`을 pull했더니 `ARCH=amd64`. Apple Silicon에서 에뮬레이션으로 돌 뻔함 (노드는 돌지만 GUI·시뮬레이션이 치명적으로 느려짐)
- 원인/해결: osrf 데스크톱 이미지는 amd64 전용이었다. 멀티아치인 `ros:jazzy` 베이스 + Dockerfile에서 `ros-jazzy-desktop`을 apt로 얹는 방식으로 전환. 앞으로 이미지는 `docker image inspect --format '{{.Architecture}}'`로 반드시 확인
- 검색 키워드: docker apple silicon amd64 emulation ros

### 2. 첫 colcon build가 세 번 죽음
- 증상: `configure_file Problem configuring file` → 파일을 옮기니 이번엔 `The manifest contains invalid XML: XML or text declaration not at start of entity: line 1, column 1`
- 시도한 것: 에러 메시지만 보고 CMakeLists와 XML 문법을 의심함 (헛다리)
- 원인/해결: 네 가지가 겹쳐 있었다 — ① 파일명이 `" package.xml"`(앞에 공백 한 칸), ② package.xml·CMakeLists.txt가 패키지 루트가 아닌 `src/` 안에 들어감, ③ `<?xml` 앞의 공백 1바이트(XML 선언은 파일의 첫 바이트여야 함), ④ hello_node.cpp가 화면엔 있는데 저장이 안 돼 디스크에선 0바이트(탭의 ● 점이 그 신호였다). 전부 "보이지 않는 것"이 원인이었고, 결정타는 `head -c 20 package.xml | xxd`로 첫 바이트가 `0x20`인 걸 눈으로 확인한 순간
- 검색 키워드: ros2 package.xml invalid XML line 1 column 1 / ament configure_file problem

### 3. 코드는 맞는데 에디터가 온통 빨간 물결
- 증상: `'rclcpp/rclcpp.hpp' file not found` 등 물결 범벅. 그런데 이건 빌드 에러와 무관했다
- 원인/해결: clangd(이해 라인)는 빌드(생산 라인)가 남기는 일지 `compile_commands.json`을 읽어야 헤더 위치를 아는데, 빌드가 한 번도 성공한 적이 없어 일지가 없었던 것. 빌드 성공 후 "clangd: Restart language server" 한 번으로 전부 소멸. 두 라인이 별개라는 걸 몸으로 배움

## 배운 것 한 줄
> 에러 메시지는 증상을 말할 뿐이다 — 원인은 종종 보이지 않는 곳(공백 한 바이트, 저장 안 된 버퍼)에 있고, 확신이 안 서면 바이트를 직접 봐라(xxd).
