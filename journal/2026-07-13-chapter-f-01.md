
## 오늘의 발견 — 제어를 몸으로 배웠다

### ① on/off 브레인의 한계 (뱅뱅 제어)
처음 브레인: `if (많이 틀어짐) 최대속도 회전; else 최대속도 전진;`
- **톱니 경로** — 회전/전진을 번갈아 하니 부드럽지 않음
- 도착 반경을 2cm로 줄이면 **영원히 맴돎**: 한 스텝 이동거리(0.5×0.1=5cm)가 도착 반경보다 커서 절대 못 들어감
- **교훈: 제어의 정밀도는 스텝 크기에 묶인다**

### ② P 제어로 전환 — if/else가 사라졌다
```cpp
omega = kTurnGain * bearing;              // 오차에 비례해 회전
v = kSpeedGain * dist * cos(bearing);     // 멀면 빠르게, 정면일수록 빠르게
// 차동구동 역변환: v,omega → 바퀴 속도 (연립방정식을 거꾸로 푼 것)
left  = v - omega*track/2;
right = v + omega*track/2;
```
- 회전과 전진을 **동시에** → 부드러운 곡선 주행
- 가까워질수록 저절로 감속 → 진동 없이 정확히 멈춤
- bearing의 **부호가 그대로 회전 방향** — 삼항 연산자 불필요 (P 제어의 우아함)

### ③ 게인 튜닝 실험 — PID 3형제를 전부 재발견
| 실험 | 현상 | 정체 |
|---|---|---|
| kSpeedGain 0.1 | 목표 **4cm 앞에서 멈춤** (v=0.004m/s로 수렴) | **정상상태 오차** → PID의 **I**가 필요한 이유 |
| kSpeedGain 3.0 | 예상과 달리 **잘 도착** | **클램프(kMaxSpeed)가 숨은 안정화 장치**였다 |
| kTurnGain 크게 + 클램프 해제 | **좌우로 부들거리며** 감 (도착은 함) | **진동** → PID의 **D**가 필요한 이유 |

**"도착했으니 됐다"가 아니라 "어떻게 도착했나"도 성능이다** — 진동하며 도착하면 서빙로봇은 국물을 쏟는다.

## 배운 것 한 줄
> P, I, D를 공식으로 외우는 것과, 각 항이 없을 때 내 로봇이 어떻게 망가지는지 눈으로 본 것은 완전히 다르다. naive-first의 결실.

## 삽질 기록
- **유령 파일**: `render.hpp`(오타 이름)와 `renderer.hpp`가 공존 → 같은 ansi 상수가 중복 정의 → 에러 폭발. `#pragma once`는 *같은 파일*의 중복만 막지, **다른 이름의 같은 내용**은 못 막는다. 파일명 바꿀 땐 옛 파일을 반드시 삭제
- **clangd 설정 뒤처짐**: 루트 `.clangd`가 ros2_ws만 가리켜서 part2의 헤더를 못 찾음 → 프로젝트별 `.clangd` 추가로 해결. 또 "두 라인"(빌드 vs 에디터) 이야기
- **거짓 성공 메시지**: 루프가 break(도착)로 끝났는지 500스텝 소진(실패)으로 끝났는지 구분 안 해서 "🐢 도착!"이 거짓말을 함 → `bool arrived` 플래그로 수정. **성공 보고 전에 진짜 성공인지 확인할 것**
