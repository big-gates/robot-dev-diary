# [Chapter L] URDF - 로봇의 구조를 코드에서 파일로 - 2026-08-16 (Week 07)

## 이번 주 목표
- 차동구동 로봇의 물리 구조(링크·조인트·센서 마운트)를 URDF(xacro)로 기술
- `robot_state_publisher` 가 그 URDF 를 읽어 TF 를 대신 발행하게 만들기
- K장에서 코드에 하드코딩한 센서 위치를 은퇴시키기
- Foxglove 로 모델과 TF 트리를 눈으로 확인

## 한 것
- 환경 준비
  - `xacro`, `joint_state_publisher`, `foxglove_bridge` 를 Dockerfile 에 추가
  - `redhat.vscode-xml` + `files.associations` 로 `.xacro` 를 XML 로 인식시킴
    (이걸 안 해서 `.xacro` 가 구문 강조 없는 평문으로 보였고, 그래서 따옴표 오타를 놓쳤다)
- URDF 작성 - 2륜 + 캐스터 + 2D LiDAR
  - `base_link`(box) / `laser`(cylinder) / 좌우 바퀴(cylinder, `continuous`) / `caster`(sphere)
  - **xacro 매크로**로 좌우 바퀴를 정의 하나로 - `${prefix}_wheel`, `${reflect * track / 2}`
  - **property** 로 치수 변수화 - `wheel_radius`, `track`, `caster_radius`
  - 캐스터 높이를 `${-wheel_radius + caster_radius}` 로 계산 - 바퀴 반지름을 바꾸면 자동으로 따라옴
- `robot_state_publisher` + `joint_state_publisher` 로 TF 발행
- **코드 은퇴** - `StaticTransformBroadcaster`, `laser_offset_x_/z_`, 관련 include 전부 제거
- `install(DIRECTORY urdf DESTINATION share/${PROJECT_NAME})` - 패키지 경로로 접근 가능하게
- Foxglove 로 3D 모델 + TF 트리 확인

## 구조 - 누가 무엇을 발행하는가
```text
odom ──────▶ base_link ──────▶ laser
  fake_robot_node      │        left_wheel   (continuous)
  (오도메트리, 코드)     │        right_wheel  (continuous)
                       │        caster
                       └── robot_state_publisher (URDF)
```

**움직이는 것은 코드가, 고정된 구조는 URDF가 기술한다.** 이 경계가 L장의 결론이다.

## 막힌 것 -> 어떻게 풀었나
- **`<link name="base_link/>` - 따옴표 하나**: XML 파서는 "line 3" 이라고 했지만 실제 원인은 2행이었다.
  파서는 `"base_link/>` 부터 다음 줄까지 통째로 문자열로 읽다가 3행에서 앞뒤가 안 맞아 신고한 것이다.
  **에러 위치는 "발각된 지점"이지 "시작된 지점"이 아니다** - C++ 에서 첫 줄만 보라고 한 것과 같다.
  그리고 `.xacro` 가 XML 로 인식되지 않아 구문 강조가 없었던 게 근본 원인이었다.
- **`Two root links found: [base_link] and [right_wheel]`**: 매크로 안의 `<child link="left_wheel"/>`
  에 `${prefix}` 를 안 붙였다. 두 joint 가 모두 `left_wheel` 을 자식으로 가리켰고, `right_wheel` 은
  부모 없이 떠서 두 번째 root 가 됐다. **URDF 는 트리라 root 가 정확히 하나여야 한다** -
  K장의 "TF 트리는 부모가 하나여야 한다"와 같은 원리인데, 이번엔 부모가 **없어서** 문제였다.
- **`<meterial>` 오타를 아무도 못 잡았다**: `check_urdf` 통과, `xacro` 통과, 그런데 캐스터만 색이
  없었다. **URDF 파서는 모르는 태그를 그냥 무시한다.** `check_urdf` 는 트리 구조만 검사하지
  내용의 의미는 보지 않는다. J장의 "빌드 통과 != 동작"의 URDF 판본.
- **URDF Preview 가 검은 화면**: `ms-iot.vscode-ros` 의 기능인데 ROS 2 + Dev Container 조합에서
  아무것도 렌더링되지 않았다. 확장 로그에는 `URDF previewing: file://...` 만 반복되고 에러가 없었다.
  원래 ROS 1 용으로 만들어진 기능이라 그런 듯. 챕터 A 에서 정한 대로 Foxglove 로 전환했다.
- **포트 8765 충돌 - 남의 로봇을 보고 있었다**: Foxglove 에 `Transforms (13)` 이 뜨고
  `base_scan`, `castor_back_right_link`, `camera_*_optical_frame` 같은 처음 보는 프레임이 나왔다.
  TurtleBot3 프레임이었다. 다른 프로젝트 컨테이너가 `-p 8765:8765` 로 **호스트 포트를 직접 점유**
  중이었고, VS Code 도 같은 포트로 포워딩을 걸어서 Foxglove 가 남의 것에 붙은 것이다.
  `lsof -nP -iTCP:8765 -sTCP:LISTEN` 에서 **두 줄이 나오면 충돌**. 우리 브리지를 8766 으로 옮겨 해결.
  **ROS 도메인은 분리돼 있었는데(우리 0, 저쪽 7) TCP 포트 레벨에서 섞였다** - DDS 격리와 포트는
  별개 층이라는 걸 배웠다.
- **`robot_state_publisher` 중복 실행**: `/robot_description` 발행자가 2개가 됐다. 각자 다른 URDF 를
  들고 있으면 "분명 고쳤는데 화면이 그대로"가 된다. `ros2 node list` 의
  `WARNING: ... share an exact name` 이 제일 빠른 신호다. `ps` 보다 이게 낫다.
- **`/robot_description` 은 latched 다**: `TRANSIENT_LOCAL` 이라 **한 번만** 발행된다. 브리지를
  갈아타거나 Foxglove 를 늦게 붙이면 놓칠 수 있다. **모델이 안 보이면 `robot_state_publisher` 재시작**
  이 해결법이고, URDF 를 수정했을 때도 마찬가지다. 파일만 고치면 반영되지 않는다.
- **URDF 에는 물리가 없다**: 캐스터 높이를 안 맞춰도 로봇이 기울어지지 않는다. URDF 는 순수
  기하학이라 링크가 공중에 떠 있어도 그대로 있다. 기울어짐은 **M장(Gazebo)에서 물리 엔진이 붙어야**
  나타난다. 지금 높이를 맞추는 것은 "바퀴와 캐스터가 같은 지면에 닿는다"는 **의도를 모델에 기록**
  하는 일이다.

## URDF 에서 확인한 것
```text
<visual> 은 TF 에 영향이 없다
   -> <visual> 을 추가해도 check_urdf 트리 출력이 그대로

<joint> 의 <origin>  = 링크가 "어디 붙는가"        -> TF 에 반영
<visual> 의 <origin> = 그 자리에서 "모양이 어떻게 놓이는가" -> 그림에만 반영

<cylinder> 는 기본이 z축 방향(세로)
   -> 바퀴로 쓰려면 <visual> 의 origin 에 rpy="1.5708 0 0" 로 눕혀야 한다
```

높이 계산도 손으로 검산했다.
```text
바퀴 바닥   = 0    - 0.08 = -0.08
캐스터 바닥 = -0.05 - 0.03 = -0.08   -> 같은 지면
```

## 검증
- `check_urdf`: root 하나(`base_link`), 자식 4개(`caster`, `laser`, `left_wheel`, `right_wheel`)
- 코드 은퇴 후 `/tf_static` **Publisher count: 1** (은퇴 전에는 2 - 코드와 URDF 가 중복 발행)
- `tf2_echo odom laser` -> `[0.200, 0.000, 0.100]`
  **`odom→base_link` 는 노드가, `base_link→laser` 는 `robot_state_publisher` 가 발행하는데
  TF 가 둘을 이어서 답을 낸다** - 어느 노드도 전체 트리를 모른다
- `view_frames` 트리가 URDF 자식 4개와 정확히 일치 (완료 기준)
- `/tmp` 에서도 `$(ros2 pkg prefix fake_robot)/share/fake_robot/urdf/...` 로 URDF 접근 성공
- Foxglove 에서 파란 몸통 + 검은 바퀴 2개 + 캐스터 + 라이다 확인
