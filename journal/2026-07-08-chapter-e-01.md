## 배운 것
- **CMake 2단계**: configure(`cmake -B build`, Makefile 생성) → build(`cmake --build build`, 실제 컴파일). Makefile은 소스가 아니라 build/ 안에 생김(out-of-source)
- **target = CMake의 명사**: add_library(부품) / add_executable(프로그램) / target_link_libraries(연결). 선언(hpp)/정의(cpp)/검사(test) 3층 분리 — 제품 코드에 테스트 main이 딸려오지 않게
- **FetchContent**: GoogleTest를 시스템 설치 없이 빌드에 포함 → 남이 클론해도 그냥 빌드됨(재현성)
- **EXPECT_NEAR(실제, 기대, 오차)**: assert의 정식 이름. 실패해도 안 멈추고, 두 값을 다 보여줌 — 여러 케이스 채점의 필수

## 오늘의 함정 두 개
- **파일명 대소문자**: `CmakeLists.txt`(소문자 m)로 만들어서 CMake가 못 찾음. macOS는 CMakeLists/CmakeLists를 같은 파일로 봐서(case-insensitive) VS Code rename도 거부. 리눅스 CI에선 "파일 없음"으로 터지는 오픈소스 단골 사고. 컨테이너 /ws가 맥 바인드 마운트라 대소문자 무시가 전파됨
- **CMake 명령 순서**: target_link_libraries(GTest 링크)를 FetchContent(GTest 생성)보다 먼저 써도 CMake가 "나중에 생기겠지"하고 미뤄서 우연히 통과. 원칙은 "의존하는 것을 먼저" — 재료 준비 → 요리 순으로 재정렬. **또 "통과했다 ≠ 옳다"**
