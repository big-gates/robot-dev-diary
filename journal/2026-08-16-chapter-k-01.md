## 한 것
- `tf2_ros`, `tf2_geometry_msgs` 배선 (`package.xml` + `CMakeLists.txt` + include)
- **`TransformBroadcaster`** — `odom → base_link` 를 500 ms 마다 발행
  - `/odom` 메시지에 채우던 값을 그대로 TF 로도 내보낸다
  - `translation` 은 `Vector3`, `position` 은 `Point` 라 통째 대입 불가.
    `rotation` 은 둘 다 `Quaternion` 이라 `transform.rotation = odom.pose.pose.orientation;` 한 줄
- **`StaticTransformBroadcaster`** — `base_link → laser` 를 `on_configure` 에서 **한 번만**
  - `/tf_static` 은 `TRANSIENT_LOCAL` 이라 늦게 켜진 노드도 저장된 값을 받는다 (I장 QoS 실습이 여기서 쓰였다)
  - `Quaternion` 기본값이 `(0,0,0,1)` 항등이라 회전 없는 마운트는 `rotation` 을 건드릴 필요가 없다
- **`Buffer` + `TransformListener`** — 변환 조회
  - `laser` 기준 `(1.0, 0, 0)` 점을 `odom` 기준으로 변환
  - 조회는 `try` / `catch (const tf2::TransformException &)` 로 감싸고 `ex.what()` 을 로그에
- J장에서 만든 라이프사이클에 네 자원 전부 통합 — `on_configure` 생성 / `on_cleanup` 해제
- 학습 노트 [TF2 프레임 트리: 왜 map → odom 이 따로 있는가](../docs/notes/chapter-k-tf-tree.md)

## 구조 - 지금 만든 트리
```text
map ──────▶ odom ──────▶ base_link ──────▶ laser
 (아직 없음)   내 노드가 발행        static, on_configure 에서 한 번
              500 ms 마다
```

`map → odom` 은 위치추정이 채울 자리라 아직 비어 있다. O장(MCL)에서 직접 만들게 된다.

## 검산으로 확인한 것
```text
로봇 원점:      laser(1.00, 0.00, 0.00) -> odom(1.20, 0.00, 0.10)
                측정 1.0 + 마운트 0.2 = 1.20,  높이 0.10

로봇 x=0.75:    laser(1.00, 0.00, 0.00) -> odom(1.95, 0.00, 0.10)
                로봇 0.75 + 마운트 0.2 + 측정 1.0 = 1.95
```

H장 문제 3-3 에서 손으로 짠 `sensor_to_map(robot, mount, sensed)` 와 **같은 답**이 나왔다.
차이는 TF 는 체인이 3단이든 5단이든 코드가 같고, 시간 보간까지 해준다는 것이다.

## 막힌 것 -> 어떻게 풀었나
- **`translation.z` 에 `theta` 를 넣어 로봇이 2.25 m 공중부양**: `tf2_echo` 의
  `Translation [0,0,2.248]` 과 `RPY yaw 2.248` 이 같은 값이라 바로 들통났다. 2D 라서
  `(x, y, theta)` 세 개라고 생각했는데 **TF 는 3D** 다 - 위치 3개 + 회전 4개(quaternion)이고
  `theta` 는 z축 **회전**이지 z축 **위치**가 아니다. `/odom` 메시지에서는 `position.z = 0.0` 으로
  제대로 넣었으면서 TF 로 옮기며 실수했다.
- **`TransformBroadcaster` 를 값 타입 멤버로 선언 -> 기본 생성자 없음**: 노드를 반드시 받아야 해서
  인자 없는 생성자가 아예 없다. `shared_ptr` 멤버로 두고 `on_configure` 에서 생성하도록 바꿨다.
  값 타입으로 생성자 초기화 리스트에서 만들 수도 있지만, 그러면 `unconfigured` 상태에서도
  `/tf` 퍼블리셔가 존재하게 되어 J장 원칙과 어긋난다.
- **`TransformListener` 를 인자 없이 생성**: Buffer 없이는 존재 이유가 없어 기본 생성자가 없다.
  `(*buffer_, this)` 로 **Buffer 참조**와 **내 노드**를 함께 넘긴다. `buffer` 가 참조 타입이라
  `shared_ptr` 을 `*` 로 역참조해야 한다. 노드를 안 넘기는 생성자도 있는데, 그건 **몰래 노드를
  하나 더 만든다**(헤더 주석에 그렇게 쓰여 있다).
- **해제 순서가 거꾸로**: listener 가 buffer 를 **참조**로 들고 있는데 buffer 를 먼저 `reset()`
  했다. 참조는 `shared_ptr` 처럼 수명을 붙잡아주지 않는다. 5회 반복해도 크래시는 안 났지만
  구조상 위험하다. **만든 순서의 역순으로 해제**가 원칙.
- **`on_configure` 에서 변환을 시도해 전이 실패**: 그 시점엔 TF 트리가 비어 있다. static 발행
  코드조차 조회 아래 줄에 있었다. 라이프사이클이 예외를 잡아 "전이 실패"로 바꿔줘서 노드는
  살았지만 `configure` 가 안 됐다. 조회는 TF 가 흐르는 `on_timer` 로 옮겼다.
- **좀비가 세 번 나왔다**: CLI `static_transform_publisher` 를 안 끄고 코드를 테스트해서
  "코드가 되는 것처럼" 보였고, `fake_robot_node` 가 2개 떠 있어서 `unconfigured` 인데 `/tf_static`
  에 laser 가 보이기도 했다. `ps -eo comm | grep -c fake_robot_node` 가 진실이다.
  `ros2 node list` 는 `kill -9` 로 죽인 노드를 **약 30초간 유령으로** 보여준다 - 정상 종료(Ctrl+C)는
  DDS 에 인사하고 나가지만 SIGKILL 은 그 과정을 건너뛰기 때문이다.
- **`view_frames` 결과를 못 찾음**: 파일명이 `frames.pdf` 가 아니라
  **`frames_<타임스탬프>.pdf`** 였다. `-o 이름` 으로 고정할 수 있고, `.gv` 는 텍스트라 컨테이너에서
  바로 읽힌다. `/ws` 가 호스트와 bind mount 이므로 거기서 실행하면 맥에서 PDF 를 열 수 있다.
- **`tf2_echo` 가 `frame does not exist`**: 노드가 `unconfigured` 였다. J장에서 만든 라이프사이클이
  의도대로 동작한 것 - `configure` + `activate` 를 해야 TF 가 나간다. `ros2 topic info /tf` 의
  **`Publisher count: 0`** 이 결정적 단서였다. 프레임 이름을 의심하기 전에 이걸 먼저 봐야 한다.

## 배운 것 한 줄
> `map → odom` 은 오도메트리의 누적 오차를 담는 자리다. 보정을 여기에 걸어야
> `odom → base_link` 의 부드러움을 지키면서 지도 기준 정확도를 얻는다.

## 남겨둔 것
- `relative_bearing` 을 TF 로 대체하지 않았다. goal 을 `base_link` 프레임으로 변환하면
  `atan2(y, x)` 한 줄이 되는데, 그러려면 `MoveToPoint.action` 의 `target_x/y` 를 프레임이 붙은
  `PoseStamped` 로 바꿔야 한다. Nav2 의 `NavigateToPose` 가 그 구조다.
- `integrate_odom` 은 좌표 변환이 아니라 오도메트리 수학이라 남는다. TF 로 대체할 성질이 아니다.
