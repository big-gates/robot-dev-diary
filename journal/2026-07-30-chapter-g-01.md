## 구조 — Set 2가 하나의 인지 파이프라인으로 맞물림
```
가짜 LiDAR (노이즈 점 구름) → fit_line (최소제곱) → 직선 = 벽
   벽1, 벽2                                      → intersect → 코너 랜드마크
SvgCanvas: 월드좌표(m) → 픽셀 (y축 뒤집기) → <svg>
```
- **fit_line의 "최소화"는 코드에 없다.** 정규방정식(closed-form) 공식이 이미 미분(∂E/∂a=0, ∂E/∂b=0)을 다 끝낸 정답이다. for문은 Σxy·Σx·Σy·Σx²를 모을 뿐. naive 버전이었다면 후보 직선 수천 개를 brute-force로 훑는 최소화 루프가 눈에 보였을 것.

## 오늘의 발견 — y=ax+b는 수직 벽 앞에서 "조용히" 거짓말한다

v1 실험 3: 오른쪽 벽을 **수직**(x=5.5 고정)으로 바꿔 돌려봤다.

| 벽 | 진짜 | fit_line 결과 |
|---|---|---|
| wallA (거의 수평) | slope 0.06 | slope 0.078 ✅ 정상 |
| wallB (**수직**) | slope = ∞ | **slope 0.556** ❌ 완만한 대각선?! |

- 복원 코너 (3.38, 1.22) vs 진짜 (5.5, 1.3) → **x가 2m 넘게 틀림**
- 그런데 **NaN이 아니다.** `0.556`은 지극히 멀쩡해 보이는 숫자.

**왜 NaN이 아닌가:**
```
slope = Cov(x,y) / Var(x)
완벽한 수직벽 :  Var(x) = 0        → 0으로 나눔 → NaN   (요란한 실패)
노이즈 낀 수직벽 : Var(x) ≈ 아주 작음 → 나눠짐    → 쓰레기 유한값 (조용한 실패)
```
노이즈(4~15cm)가 x를 살짝 흔들어 분모를 "정확히 0"이 아니게 만들었다. 그래서 0으로 나누기를 아슬아슬 피하고, 점 40개의 우연한 상관관계로 그럴듯한 오답을 낳았다. (sigma=0으로 두면 진짜 `slope=nan`, `corner=(nan,nan)`이 뜬다 — 요란한 버전.)

**이게 NaN보다 위험한 이유:**
- NaN이면 `std::isnan()`으로 감지·대처 가능 → 시끄럽게 실패
- 지금은 아무도 에러로 안 본다. 로봇은 "벽은 대각선이고 코너는 2m 저쪽"이라고 **확신에 차서 틀린다**. 서빙로봇이라면 엉뚱한 테이블로 국물을 나른다.
