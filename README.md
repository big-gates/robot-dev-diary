# robot-dev-diary — 로봇 개발 A to Z

> 서빙로봇 위에 앱을 얹던 개발자가, SDK 아래층(자율주행 스택·멀티로봇)을 직접 구현하며 로봇 개발자가 되어가는 공개 일기.
>
> A public build-in-the-open diary: an application engineer working on production serving robots, hand-implementing the autonomy stack below the vendor SDK — from modern C++ to SLAM, Nav2, and multi-robot orchestration. Korean first; English summaries per chapter as they mature.

## 이 로드맵은 누구를 위한 것인가

- 백엔드/앱 개발자인데 로봇 소프트웨어로 넘어오고 싶은 사람
- 로봇 SDK(제조사 API)를 *사용*해봤지만, 그 아래에서 무슨 일이 일어나는지 직접 만들어보고 싶은 사람
- 강의 수집 대신 **한 대의 로봇을 바닥부터 굴려보는 것**으로 배우고 싶은 사람

전제: 프로그래밍 경험 있음(언어 무관), 로봇 지식 0, 주 10–15시간, 약 12개월.

## 다섯 가지 규칙

1. **모든 코드는 손으로 타이핑한다.** 복사-붙여넣기, 생성 코드 금지. 이해하지 못한 줄은 커밋하지 않는다.
   - AI 사용 정책: 설명·리뷰·디버깅 질문은 적극 활용(과외 선생 모드), 인라인 자동완성과 코드 생성은 Part 3 완주까지 금지. 문답에서 나온 개념 정리는 [docs/notes/](docs/notes/)에 쌓는다.
2. **naive-first.** 프로덕션 도구(slam_toolbox, AMCL, Nav2)를 쓰기 전에, 같은 문제를 조악하게라도 직접 구현한다. "내가 만든 것 vs 프로덕션"의 격차가 최고의 교재다.
3. **매주 일기 1편.** 성공담보다 막힌 지점과 삽질이 더 중요한 콘텐츠다. ([일기 템플릿](docs/journal-template.md))
4. **챕터를 끝내면 git tag를 단다** (`chapter-a`, `chapter-b`, …). 따라오는 사람은 태그 단위로 체크아웃한다.
5. **커지면 졸업시킨다.** 챕터 산출물이 독립 프로젝트가 되면(시뮬 월드, fleet adapter 등) 별도 레포로 분리하고 여기서 링크한다.

## Part 0 — 준비 (1주)

### A. 개발 환경 구축
macOS(Apple Silicon)에서 ROS 2는 네이티브 지원이 없다. Docker 컨테이너(Ubuntu 24.04 + ROS 2 Jazzy)를 기본 무대로, IDE는 CLion(비상업 무료)을 쓴다. 시각화는 헤드리스 시뮬 + Foxglove로 우회하는 게 맥에서 가장 쾌적하다.
- 만들 것: 재현 가능한 개발 환경 — `Dockerfile` + 실행 스크립트, C++ hello-world ROS 2 노드가 컨테이너에서 빌드·실행
- 완료 기준: 새 맥북에서 30분 안에 같은 환경을 재현할 수 있는 문서 ([docs/setup-macos.md](docs/setup-macos.md))
- 일기 포인트: "로봇 개발의 첫 관문은 로봇이 아니라 리눅스였다"
- 학습 노트: [C++/ROS 2 툴체인의 큰 그림](docs/notes/chapter-a-toolchain.md) — colcon·CMake·make/ninja·g++·clangd·rcl/rclcpp·ament의 관계 총정리

## Part 1 — Modern C++ 코어 (4–6주) — ROS 없이

> 목표: ROS를 배우기 전에 C++ 그 자체를 손에 붙인다. 모든 예제는 로봇 수학·통신이라는 실제 문제로 한다.

### B. CMake를 맨손으로 (1주)
IDE 매직 없이 target, library, 컴파일 플래그, `find_package`를 직접 쓴다. 이후 모든 챕터의 빌드는 여기서 익힌 CMake로 한다.
- 만들 것: 실행 파일 + 정적 라이브러리 + 외부 의존성 하나를 엮은 3-타깃 프로젝트
- 완료 기준: `cmake -B build && cmake --build build`가 무슨 일을 하는지 남에게 설명 가능

### C. 포즈 수학 라이브러리 `libpose2d` (2주)
Vec2, SE(2) 강체변환, 각도 정규화(wrap), 변환 합성·역변환을 직접 구현한다. RAII, 값 의미론, `constexpr`, 연산자 오버로딩, 이동 의미론을 여기서 체득한다.
- 만들 것: 헤더 온리 라이브러리 + 유닛 테스트
- 완료 기준: "로봇 기준 좌표 → 지도 좌표" 변환 체인 테스트 통과
- 일기 포인트: 이 라이브러리는 H장에서 TF2에 은퇴당한다 — 그때 "TF2가 왜 필요한가"를 몸으로 안다

### D. 테스트와 품질 도구 (1주)
GoogleTest, clang-format, clang-tidy, 새니타이저(ASan/UBSan)를 프로젝트에 붙인다. 이후 전 챕터의 기본 장비.
- 완료 기준: `libpose2d`에 CI급 품질 게이트(포맷·린트·테스트) 로컬 스크립트 완비

### E. 동시성과 미니 pub/sub (1–2주)
스레드, 뮤텍스, 아토믹, 콜백 큐를 익히고 프로세스 내 미니 pub/sub 메시지 버스를 만든다. MQTT/JMS를 다뤄봤다면 이 장에서 "브로커를 라이브러리로 축소하면 뭐가 남는가"를 보게 된다.
- 만들 것: 토픽 기반 in-process 메시지 버스 (스레드 안전, 백프레셔 나이브 버전)
- 일기 포인트: F장에서 ROS 2 executor를 만나면 이 장의 설계와 비교한다

## Part 2 — ROS 2 기초 (6–8주)

### F. 노드·토픽·QoS (1–2주)
rclcpp로 퍼블리셔/서브스크라이버를 작성하고, QoS(reliability, durability, history)를 MQTT QoS와 대조하며 익힌다.
- 만들 것: 가짜 로봇 — 속도 명령(`cmd_vel`)을 적분해 odom을 퍼블리시하는 C++ 노드
- 완료 기준: QoS 미스매치로 메시지가 안 오는 상황을 일부러 만들고 원인을 설명

### G. 서비스·액션·라이프사이클 (1–2주)
요청-응답(서비스), 장기 작업(액션), 관리형 노드(라이프사이클), executor와 콜백 그룹.
- 만들 것: "지점으로 이동" 액션 서버 — 가짜 로봇이 목표점까지 odom 적분으로 이동, 진행률 피드백
- 일기 포인트: 서빙로봇 SDK의 navigation API가 사실 액션이었다는 것을 여기서 깨닫는다

### H. TF2 — 내 라이브러리를 은퇴시키기 (1주)
좌표 프레임 트리(map → odom → base_link → laser), 시간 보간, `tf2_ros` broadcaster/listener.
- 만들 것: C장의 `libpose2d` 사용처를 TF2로 전면 교체
- 완료 기준: "왜 map→odom이 별도 프레임인가"(위치추정 보정의 자리)를 그림으로 설명

### I. URDF로 로봇 정의하기 (1주)
차동구동 로봇의 링크·조인트·관성·센서 마운트를 URDF(xacro)로 기술, `robot_state_publisher` + RViz로 확인.
- 만들 것: 2륜 + 캐스터 + 2D LiDAR 구성의 내 로봇 모델
- 완료 기준: RViz(또는 Foxglove)에서 TF 트리와 모델이 일치

### J. Gazebo 시뮬레이션 (2주)
gz-sim에 URDF 스폰, 차동구동·LiDAR 센서 플러그인, ros_gz 브리지. 여기서 만든 월드가 이후 전 챕터의 무대다.
- 만들 것: 레스토랑풍 월드(테이블·통로) + 손으로 짠 C++ 텔레옵 노드
- 완료 기준: 키보드로 시뮬 로봇 주행, LiDAR 스캔이 토픽으로 흐름
- 졸업 후보: 이 월드는 커지면 `serving-sim` 독립 레포로 분리

## Part 3 — 자율주행 원리를 맨손으로 (8–10주) ★ 이 일기의 심장

> 목표: 프로덕션 도구가 풀어주는 문제를 먼저 조악하게 직접 푼다. 면접에서 "AMCL이 왜 수렴하는지 그림으로 설명"이 가능해지는 구간.

### K. 오도메트리와 데드레커닝 (1주)
휠 엔코더 모델에서 포즈 적분, 누적 오차의 체감. 시뮬에서 odom만으로 주행 궤적을 그리고 실제(ground truth)와 비교.
- 완료 기준: 오차가 왜, 어떤 패턴으로 쌓이는지 데이터로 보여주는 일기 1편

### L. 점유 격자 매핑 (2주)
알려진 포즈 가정 하에 LiDAR 스캔으로 log-odds 점유 격자 지도를 직접 만든다. 레이캐스팅(Bresenham), 확률 업데이트.
- 만들 것: 시뮬 주행하며 실시간으로 자라는 내 매핑 노드 (C++)
- 완료 기준: 내 지도와 slam_toolbox 지도의 육안 비교 스크린샷

### M. 파티클 필터 위치추정 — MCL (2–3주)
모션 모델, 측정 모델(likelihood field), 리샘플링을 직접 구현해 L장의 지도 위에서 로봇을 위치추정한다.
- 만들 것: 파티클 구름이 수렴하는 과정을 시각화하는 MCL 노드
- 완료 기준: 납치된 로봇(kidnapped robot) 상황에서 재수렴 데모
- 일기 포인트: 베이즈 필터 수식을 코드 한 줄 한 줄에 대응시켜 기록

### N. A* 전역 계획 (1–2주)
격자 지도 위 A*를 직접 구현, 휴리스틱·타이브레이킹·경로 스무딩까지.
- 만들 것: 지도 클릭 → 경로 생성 노드
- 완료 기준: 막힌 통로를 막았을 때 대안 경로가 즉시 나오는 데모

### O. 경로 추종 제어기 (1–2주)
Pure Pursuit(또는 DWA 나이브 버전)로 N장의 경로를 실제로 따라가게 한다. 전방주시거리, 속도 프로파일, 장애물 앞 정지.
- 완료 기준: K~O를 엮은 풀 파이프라인 — 내 지도 + 내 위치추정 + 내 플래너 + 내 제어기로 시뮬 로봇이 목적지 도달

### P. 프로덕션 스택으로 교체 — 그리고 비교 (1주)
같은 로봇·같은 월드에 slam_toolbox + AMCL + Nav2를 올리고, 내 구현과 성능·강건성·설계를 항목별로 비교하는 긴 일기를 쓴다.
- 완료 기준: "내가 만든 것은 어디서 부서지고, 프로덕션은 그걸 어떻게 푸는가" 비교표
- 이 일기가 이 레포의 대표 콘텐츠가 된다

## Part 4 — Nav2 제대로 (6–8주)

### Q. Nav2 아키텍처와 튜닝 (2주)
BT Navigator, planner/controller/behavior 서버, costmap 레이어 구조, 파라미터 튜닝. J장의 레스토랑 월드에서 좁은 통로·동적 장애물 시나리오로 튜닝 근거를 문서화.
- 완료 기준: 파라미터 하나하나에 "왜 이 값인가"가 달린 튜닝 노트

### R. 커스텀 costmap layer 플러그인 (2–3주) ★ 킬러 산출물
C++로 pluginlib 기반 costmap layer를 저작한다. 주제: **human-aware etiquette layer** — 감지된 사람 주변에 감속·회피 비용 부여 (서빙로봇 현장 경험의 공개 버전).
- 완료 기준: 사람 접근 시 감속이 costmap 시각화로 확인되는 데모 + 영문 README

### S. Behavior Tree 커스텀 노드 (1–2주)
BT.CPP로 커스텀 액션/컨디션 노드를 작성해 Nav2 동작 흐름을 바꾼다 (예: "혼잡하면 대기 후 재시도").
- 완료 기준: 기본 BT와 내 BT의 동작 차이 데모

### T. 실물 하드웨어 포팅 — 하드웨어 트랙 (3–4주, 병행 가능)
RPLiDAR + SBC(Jetson/RPi) + 차동구동 베이스로 시뮬 스택을 실물에 올린다. 오도메트리 캘리브레이션, 센서 마운트 오프셋, 실환경 튜닝.
- 완료 기준: 집/사무실 지도 작성 → 목적지 주행 → 사람 회피 영상
- 예산: 자작 약 60–70만 원 (시뮬만으로 U장 진행도 가능 — 늪에 빠지면 과감히 스킵)

## Part 5 — 멀티로봇 (8–10주) ★ 포트폴리오의 킬러 피스

### U. 멀티로봇 시뮬과 naive 트래픽 매니저 (2–3주)
네임스페이스로 로봇 3대 + 각자 Nav2 스택. 좁은 복도 교차 상황에서 데드락을 직접 목격한 뒤, 예약 테이블 기반 나이브 중앙 트래픽 매니저를 C++로 만든다.
- 완료 기준: 나이브 매니저로 데드락 해소 데모 + 한계 기록

### V. Open-RMF fleet adapter (3–4주)
RMF 개념(fleet adapter, traffic negotiation, task dispatch)을 익히고 내 시뮬 로봇용 fleet adapter를 작성한다. 문/리프트 mock 연동 1개 포함.
- 완료 기준: 로봇 3대가 1.5m 복도에서 데드락 없이 교차 통행 10회 연속
- 졸업 후보: fleet adapter는 독립 레포로

### W. 플릿 관제 대시보드와 SLO (2–3주)
라이브 관제 대시보드(디지털트윈)와 Prometheus 플릿 메트릭(미션 성공률, 협상 지연, MTTR). 백엔드 경력자의 초능력을 로봇에 이식하는 장.
- 완료 기준: 분할 화면(시뮬 + 대시보드) 3분 데모 영상

## Part 6 — 세상에 내놓기 (M10–M12, 병행)

### X. 업스트림 기여
Part 3–5에서 만난 문서 구멍·버그를 Nav2/Open-RMF에 되돌린다. 이슈 트리아지 → 문서 → 버그픽스 → 기능 순.
